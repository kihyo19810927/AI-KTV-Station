# ADR-0004：桌面数据库操作作用域与歌手统计缓存

状态：Accepted（KTVS-088，第一阶段）

桌面直接调用单例 DbContext，SQLite 的同步执行和全库歌手聚合会阻塞 Dispatcher；仅限制卡片数量不足以解决问题。

采用显式桌面数据门面：每个完整用例在 Task.Run 内从内嵌 Server 创建并释放 AsyncServiceScope。ViewModel 只在返回后更新 UI。Server 的 scoped DbContext 是操作内工作单元，写入相关实体保留跟踪，纯读取禁用跟踪。队列锁、播放器和统计缓存由同一个 Server 提供，避免桌面和手机形成两套锁。

歌手统计在 SQL 中预聚合，每次冷加载只返回歌手级结果；同一数据库的分组请求复用内存快照，30 秒到期，相关 SaveChanges 成功后主动失效。并发冷请求共享加载锁，失败与取消不缓存。外部数据库写入最迟在到期后反映。

本阶段保留 WPF；只修正布局尺寸、状态条颜色及性能。便携 JSON 曲库的媒体定位使用设置中的本机挂载根路径；导入时按逻辑源名重映射已有源并复用相对路径，绝不因盘符变化创建另一份曲库。Web /desk、管理 API 和托盘启动器在此 PR 经用户通过后实施。
