# ADR-0004：SQLite 持久化与搜索

状态：Accepted  
日期：2026-09-03

## 决策

- V1 使用单机 SQLite，EF Core 负责事务、迁移和常规数据访问，SQLite FTS5 负责全文搜索。
- 歌曲身份与媒体可用性分离：远端离线只更新 `MediaAsset`/`MediaSource` 状态，不删除 `Song`。
- 扫描只读媒体；默认变化检测使用规范化路径、大小和修改时间，避免远端全文件哈希。
- 队列、房间、人工元数据、音轨映射和扫描检查点持久化，不使用静态全局状态作为事实来源。
- 数据库迁移前备份；数据库文件、备份与日志不提交仓库。

## 后果

部署简单且支持离线运行。写操作需控制并发和事务长度；100k/300k 数据的搜索与扫描性能必须在后续门禁量化。
