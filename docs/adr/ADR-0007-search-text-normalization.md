# ADR-0007：中文搜索文本规范化

状态：Accepted

日期：2026-09-07

## 背景

V1 必须支持原文、简繁兼容、汉语拼音、拼音首字母、英文和数字紧凑形式搜索。规范化发生在写入索引时，搜索请求不能访问媒体文件。中文转换词典不适合在项目中自行维护，且具体库不应渗入领域或应用规则。

## 决策

- 应用层定义 `ISearchTextNormalizer` 和稳定的 `SearchTextKeys`，基础设施层实现第三方转换。
- 采用 `ToolGood.Words` `3.1.0.3`。官方 NuGet 包提供 .NET 8/.NET Standard 2.1 资产、无传递依赖，支持拼音、首字母及简繁转换；源码仓库采用 Apache-2.0。版本由中央包管理和 lock file 固定。
- 所有输入先执行 Unicode NFKC、Invariant 小写和空白规范化；紧凑键只保留 Unicode 字母与数字。
- 同时预计算规范化原文、简体、繁体、无音调拼音、拼音首字母和紧凑键。未知字符保留在原文键中，转换异常不得阻止歌曲入库。
- `Song` 和 `Artist` 只保存转换后的字符串，不引用转换库；扫描器通过应用端口填充字段。

## 备选方案

- `ToolGood.Words.Pinyin`：首次加载较快且为 MIT，但只解决拼音，仍需另一个简繁库；当前包体积也大于完整包。
- `OpenccNetLib` + 独立拼音库：转换质量和区域配置更丰富，但引入两套依赖、外部字典部署及更多初始化面，V1 暂不采用。
- 自维护字符表：无法可靠处理多音词和词组，维护成本及正确性风险不可接受。

## 后果

第三方库被限制在 Infrastructure，可替换且不会污染领域层。代价是首次转换需要加载内置词典，部署包增加数 MiB；KTVS-018 的 100k 性能基线必须包含预计算成本与查询 P95。简繁搜索键是召回辅助，不作为显示文本或人工元数据回写来源。
