# 房间生命周期

KTVS-027 建立单一开放房间的 Application 服务。创建房间时验证每位访客队列上限、分配全历史唯一的 6 位加入码并拒绝同时存在第二个开放房间；SQLite 对开放房间槽位设置唯一索引，作为并发写入的最终防线。关闭操作幂等并记录关闭时间。`GetCurrentAsync` 从仓储查询开放房间，因此应用重启后可从 SQLite 恢复，而不依赖进程内缓存。

加入码生成位于 Infrastructure，使用密码学随机数和去除易混淆字符的字母表。加入码不是主持人永久密钥；短期访客/主持人令牌、过期、撤销和权限矩阵由 KTVS-028 实现。公共房间 DTO 不包含媒体路径、云盘信息或令牌哈希。
