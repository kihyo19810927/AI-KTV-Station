# AI-KTV Station 运维手册

本手册面向 Windows 11 家庭 KTV 主机维护者。Station 管理本地索引、房间、队列和播放；AI-KTV-Builder 继续负责制歌。任何运维操作都不得移动、重命名、覆盖或删除真实媒体。

## 1. 安装与目录

按 [Windows 发布包与安装](WINDOWS-INSTALLATION.md)核对 SHA-256 并解压自包含 ZIP。运行文件为 `Station.Desktop.exe`。V1 不捆绑 mpv、FFmpeg 或 ffprobe，必须由主机管理员从可信来源单独安装。

默认数据位置：

- 程序目录 `data/station.db`：歌曲索引、收藏、历史、房间和人工修正。
- 数据库旁 `data/backups`：有待迁移时自动生成的升级前备份。
- `%LOCALAPPDATA%\AI-KTV Station\settings.json`：本机设置。
- `%LOCALAPPDATA%\AI-KTV Station\logs`：受限轮转诊断日志。
- `%LOCALAPPDATA%\AI-KTV Station\diagnostics`：用户主动导出的脱敏报告。

不要把以上用户数据放入发布 ZIP、Git 或公开问题单。

## 2. 配置

首次启动默认监听 `0.0.0.0:5090`，二维码使用主机可达的明确局域网 IPv4 地址。若只做本机验证，可在设置页改为 `127.0.0.1`；手机点歌时不要使用回环地址。禁止使用域名、非明确地址或公网端口映射。Windows 防火墙如需放行，只允许家庭 LAN 配置文件和 Station 端口，完成后用同 Wi-Fi 手机验证。

播放器路径留空时会从 `PATH` 和 WinGet 常见目录定位 mpv。FFmpeg/ffprobe 需在 `PATH` 可定位。媒体源应指向 CloudDrive/CloudDrive2 的已挂载子目录；先添加 5–20 首的小目录，确认后手动扫描。添加来源不会自动扫描。

## 3. 启动、运行与停止

1. 先确认 CloudDrive 挂载在线，再启动 `Station.Desktop.exe`。
2. 仪表盘应显示 SQLite、mpv 和内嵌点歌服务状态。
3. 创建房间并用手机扫码；二维码不得包含令牌或文件路径。
4. 正常结束时先关闭房间，再关闭主窗口。程序会停止 Kestrel 和自有 mpv 进程。

异常退出后再次启动会把 Preparing/Playing/Paused 队列项恢复为 Waiting，并以稳定错误码闭合未结束历史。它不会删除歌曲索引。

## 4. 备份与恢复

日常备份必须在 Station 完全退出后进行：

1. 确认 `Station.Desktop.exe`、独立 Server 和 mpv 均已退出。
2. 将整个程序 `data` 目录复制到带日期的独立位置。
3. 同时复制 `%LOCALAPPDATA%\AI-KTV Station`，但对外分享前必须使用应用内脱敏诊断导出。
4. 在备份副本上执行 SQLite `PRAGMA integrity_check`；返回 `ok` 才可作为恢复点。

升级过程详见 [数据库升级、备份与恢复](DATABASE-UPGRADE.md)。不得删除正式 `station.db` 后重扫：这样会丢失收藏、历史、房间与人工修正。恢复时先保留故障库副本，再在隔离目录验证备份，最后核对关键业务记录。

## 5. 曲库运维

- 扫描器只读媒体，按来源增量更新索引。
- MKV、MPG/MPEG 等视频入库；KSC 只关联歌词；RAR 忽略；NFO 可选。
- 远端文件暂不可用时标记 Offline/Unreadable 并记录错误，不删除索引。
- 恢复挂载后只重扫受影响来源。小批真实 115 验收通过后，再按年度或目录逐批扩展；不得直接扫描整个挂载根目录。
- 人工元数据与音轨映射优先级高于 NFO 和文件名，重扫不得覆盖。

## 6. 故障排除

### 点歌页面无法打开

确认仪表盘“点歌服务”可连接、设置中的 IP 属于当前 LAN、手机与主机在同一 Wi-Fi，且路由器没有客户端隔离。先从主机访问 `http://<配置IP>:<端口>/health`。不得为排障开放公网。

### mpv 不可用或播放停止

运行 `scripts/verify-environment.ps1`（源码环境）或确认 WinGet 的 mpv 安装。检查播放器配置，不要把 IPC 内容或媒体路径发给手机。可重试故障由恢复策略有限重试；系统性错误会停止自动播放并等待主机处理。

### CloudDrive 断挂、403 或文件不可读

先恢复 CloudDrive/115 挂载，不要删除媒体源或数据库。确认小目录可读后执行该来源增量重扫。索引、收藏、历史和人工映射应保留；若未保留，立即停止全库扫描并导出诊断。

### 数据库升级失败

停止程序，保留当前库和 `data/backups`。应用已尝试自动恢复升级前快照；按数据库恢复文档核对完整性和关键记录。禁止删库重建。

### 端口占用或启动失败

选择 1024–65535 的未占用端口，保存后重启。不要使用 `0.0.0.0` 以外的非明确地址表示法；如需 LAN，填写主机明确 IPv4。日志中只应出现公开错误摘要。

## 7. 诊断、安全与升级节奏

优先通过“诊断”页导出脱敏报告。提交报告前再次确认不含真实媒体路径、连接串、房间令牌、Cookie 或云盘凭据。房间令牌短期有效且只存哈希；关闭房间或撤销访客后旧令牌应失效。

每次升级按以下顺序：校验包 → 在测试目录启动 → 备份正式数据 → 小库迁移演练 → 升级 → 核对收藏/历史/人工修正 → 小批媒体播放 → 再恢复日常使用。版本回退必须配套使用与旧版本兼容、已验证的数据库备份。

## 8. 验收与升级联系点

完整场景使用 [用户验收测试包](USER-ACCEPTANCE-TEST.md)，发布门禁使用 [发布检查清单](RELEASE-CHECKLIST.md)。真实电视、功放、手机、115 小批目录、突然断电和干净 Windows 安装必须明确标记为待实机验收，不能以自动化结果代替。
