# 进程与启动恢复

KTVS-051 为 Windows 主控和服务端增加幂等启动恢复步骤。SQLite 迁移完成后，所有因上次进程中断而遗留在 `Preparing`、`Playing` 或 `Paused` 的队列项会在一个事务中回到 `Waiting`；对应尚未结束的播放历史会以 `Failed`、`playback.interrupted_by_restart` 和恢复时间闭合。随后正常播放编排可重新选择这些等待项。

恢复不会删除队列、歌曲、媒体、收藏或历史，也不会假设上次 mpv 进程仍存活。已经完成、跳过或失败的队列项不改变；重复执行恢复得到零变更，因此服务启动重试是安全的。

自动验证覆盖 SQLite 文件关闭后用新 DbContext 重开、三种活动队列状态、未闭合历史、重复恢复，以及真实 mpv 子进程被终止后的可重试故障事件。操作系统突然断电、磁盘写缓存和 Windows 自动启动仍需实机验收；正式演练前必须备份数据库，禁止通过删库恢复。
