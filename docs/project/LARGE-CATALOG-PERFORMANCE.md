# 大曲库性能基线

KTVS-049 在当前开发主机上使用完全合成、可重复生成的数据验证 100k 与 300k 规模。命令：

```powershell
pwsh.exe -ExecutionPolicy Bypass -File scripts/test-search-performance.ps1
```

2026-09-10 详细复跑结果：

| 场景 | 规模 | 结果 |
|---|---:|---:|
| SQLite FTS 混合查询，30 样本 | 100,000 | P95 4.18 ms，最大 9.19 ms |
| SQLite FTS 混合查询，30 样本 | 300,000 | P95 12.54 ms，最大 15.07 ms |
| 扫描应用层枚举与元数据建模 | 100,000 | 0.51 s，约 196,349 项/秒 |
| 扫描应用层枚举与元数据建模 | 300,000 | 1.99 s，约 150,919 项/秒 |

搜索基线使用真实 SQLite FTS 表、查询编译、计数、排序和分页。扫描基线使用流式生成的媒体条目和轻量计数仓储，覆盖分类、文件名解析、歌曲/媒体建模、检查点及状态统计；它刻意不包含 Windows/CloudDrive 文件系统延迟、ffprobe 成本和 EF Core 写盘，因此不能作为全库扫描耗时承诺。

真实性能验收仍按安全顺序进行：先扫描一个用户选定的小批 115 目录，确认格式和元数据，再逐年度追加；全库扫描及低规格主机资源占用待实机记录。任何性能测试都不要求删除现有数据库。
